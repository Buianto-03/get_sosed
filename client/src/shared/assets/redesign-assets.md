# Ресурсы редизайна

Карта ресурсов для экранов GETSOSED по опубликованному макету. Фото находятся в client/public и доступны приложению по пути от корня сайта.

## Фотографии

| Использование | Локальный файл | Кадрирование |
| --- | --- | --- |
| Баннер главной и «О нас» | client/public/redesign-hero-{480,768,1280}.{avif,webp}; JPEG fallback client/public/redesign-hero.jpg | Точная фотография из опубликованной версии 1, сверена 1 ноября 2026. object-fit: cover, центр; на телефоне center 55%. Обёртка определяет геометрию: фотография не увеличивает высоту desktop-баннера. |

Фотографии объявлений приходят из API; публикация использует выбранные пользователем
File-объекты. Статический `redesign-hero.jpg` лежит в корне public: `/images`
направляется на API и не подходит для ресурса оболочки. Знак дома собирается
из иконки и текста GETSOSED; `logo.png` используется как favicon.

## Шрифт

- Семейство: Inter, полный variable-диапазон весов 100–900 и исходная ось opsz 14–32. Сохранены все 2 933 глифа и 2 849 кодовых точек, включая кириллицу.
- Загрузка браузером: client/public/fonts/Inter-Variable.woff2 (350 460 байт).
- Исходник для воспроизведения: client/public/fonts/Inter-Variable.ttf; лицензия — client/public/fonts/OFL.txt.
- Источник: официальный репозиторий Google Fonts, каталог Inter; лицензия SIL Open Font License.
- Подключение через @font-face находится в `shared/styles/foundations.scss`.

## Оптимизация O02

HeroImage выбирает AVIF → WebP → исходный JPEG. Варианты имеют ширину
480, 768 и 1280 px, пропорции 4:3; кадрирование задают существующие стили
баннеров. `sizes` учитывает ширину SiteContent, его отступы и переход
к одноколоночной компоновке. Баннер оказался LCP-элементом обоих маршрутов
на desktop/mobile: используется eager и высокий приоритет. Для React 18.2
атрибут fetchpriority передаётся в нижнем регистре. Preload не добавлен.

| Ширина | AVIF, байт | WebP, байт |
| --- | ---: | ---: |
| 480 | 18 846 | 24 764 |
| 768 | 33 415 | 46 372 |
| 1280 | 59 127 | 84 890 |

Воспроизведение из корня репозитория (нужны установленные зависимости server,
содержащие sharp 0.33.5). Генераторы перезаписывают только производные ресурсы.
Исходный JPEG не имеет завершающего маркера; sharp декодирует его с
`failOn: 'none'`, сохраняя существующее изображение, как это делает браузер.

```sh
node client/scripts/optimization-assets/banner.mjs
python3 -m venv /tmp/get-sosed-o02-font-env
/tmp/get-sosed-o02-font-env/bin/pip install 'fonttools[woff]==4.60.2' 'brotli==1.2.1' 'zopfli==0.2.3.post1'
/tmp/get-sosed-o02-font-env/bin/python3 client/scripts/optimization-assets/font.py
```

Каталог шрифтов сохраняет TTF как исходник; CSS загружает только WOFF2
с font-display: swap. Конвертация не сокращает набор символов или оси
и проверяет их совпадение после обратного чтения WOFF2.

В галерее первая фотография загружается сразу. IntersectionObserver допускает
создание остальных img только при видимости плиток внутри галереи; показанные
фото сохраняются при дальнейшей навигации. Это предотвращает запросы скрытых
фотографий, которые Chrome может выполнять при повторном открытии даже с
loading=lazy. Если IntersectionObserver недоступен, остаётся native lazy loading.
Существующая карусель карточек сохраняет свою загрузку соседних фото по требованию.

Фотографии объявлений пока представлены одним URL: API не предоставляет
размеры или thumbnail. На сервере публикация переводит фото в WebP без resize.
Для сокращения их сетевого объёма потребуется отдельная задача: генерация
уменьшенных вариантов при публикации, обработка существующих файлов и
добавление их URL/размеров в контракт. В O02 этот контракт не менялся.
