# GETSOSED: план вёрстки экранов и внедрения собственного UI kit

Дата: 12 октября 2026. Обновлено: 13 октября 2026. Статус: выполнены P01–P03 и K01–K11 (14 из 40 задач). B01–B05, V01–V18 и Q01–Q03 ожидают приёмки. Девять экранов в независимом preview пока служат демонстрационным каркасом, а не завершёнными экранными компонентами.

Этот документ заменяет предыдущий план перехода. Объём работ: собственный UI kit, адаптивная вёрстка экранов, демонстрационные данные и локальные состояния интерфейса. Backend, API, база данных, WebSocket, реальная авторизация и сохранение данных в этот этап не входят.

Актуальный визуальный ориентир: [опубликованный макет GETSOSED](https://getsosed-visualization-2026.heartyfawn5.chatgpt.site), сверенный 12 октября 2026 года на desktop/tablet/mobile. Исходная [Figma GETSOSED · Warm Neutral](https://www.figma.com/design/SmkHHTyUKc5FWCpf9dhU8y?node-id=0-1) остаётся ориентиром для профиля, чата и публикации, которые гостевой сайт не показывает. При расхождении для доступных экранов ориентироваться на опубликованный макет и обновлённую спецификацию.

## Что получаем в конце

- Собственный GETSOSED UI kit: токены, React-компоненты, варианты, состояния и документация использования.
- Каталог UI kit, где каждый компонент можно проверить отдельно.
- Все восемь экранов макета, четыре шага публикации и дополнительные виды регистрации/редактирования профиля в едином стиле.
- Desktop, tablet и mobile для каждого экрана.
- Отдельное превью, которое открывается без сервера и позволяет переключать демонстрационные состояния.
- Экранные компоненты получают данные и обработчики через props; вёрстка не зависит от транспорта, сессии или глобального store.

## Устройство собственного UI kit

Предлагаемая основа — React + TypeScript, CSS Modules и CSS custom properties. Это компоненты проекта с собственными свойствами и стилями, а не только настройка темы Chakra.

Текущая Chakra может оставаться в прежних экранах на время перехода. Для сложных доступных элементов, например Modal/Drawer/Menu, допустимо использовать её существующие примитивы внутри приватного адаптера UI kit. Публичные свойства, токены и импорты новых экранов принадлежат GETSOSED; компоненты страниц не используют Chakra напрямую. Удаление библиотеки целиком не является критерием этого этапа.

Текущее размещение подготовки и целевые слои экранных блоков относительно `client/src/`:

```text
shared/ui/
  button/                # компонент, типы, CSS Module
  field/
  input/
  selection/
  ...
  README.md              # правила использования и добавления компонентов
shared/styles/
  _tokens.scss           # общие Sass-токены UI kit
preview/
  main.tsx               # отдельная точка входа без запуска приложения
  UiFoundationsShowcase.tsx # каталог UI kit
  fixtures.ts            # демонстрационные объекты и наборы состояний
  PreviewApp.tsx         # каркас, постепенно заменяемый экранными компонентами
entities/advert/ui/      # карточка и галерея объявления
features/.../ui/         # представления фильтров и форм
widgets/.../ui/          # шапка, профиль, список диалогов
pages/.../ui/            # сборка экранов из готовых частей
```

Отдельный вход `client/preview.html` открывает каталог и каркас экранов через Vite. Preview не импортирует основной `App`, `ProtectedRoute`, store или сервисы запросов. Fixtures используются только в preview; новые экранные компоненты не импортируют демонстрационные данные. Каталог и preview доступны в разработке и не включаются в production-вход.

UI kit хранит универсальные элементы: Button, Input, Avatar, Badge, Surface. Карточка объявления, строка диалога и форма публикации относятся к предметным блокам и собираются из UI kit в соответствующих слоях проекта. Соблюдается направление импортов FSD.

Правила компонентов:

- Небольшой публичный API: `variant`, `size`, `disabled`, `loading` и нативные HTML/ARIA-свойства по назначению; без переноса всего API стилевых props Chakra.
- Значения перечислимых пропсов UI kit объявлять отдельными экспортируемыми TypeScript `enum`, не union type.
- Формы поддерживают `value`/`onChange`, подпись, подсказку и ошибку; идентификаторы полей и связей доступности уникальны.
- Цвета, интервалы, радиусы и типографика берутся из токенов. Специфические размеры композиции задаются на уровне блока или страницы.
- В каталоге рядом показаны все реализованные варианты, интерактивные состояния и пример использования.
- Новые экраны используют UI kit сразу; повторяющееся оформление исправляется в одном месте.

## Порядок внедрения

1. P01–P03 и K01–K11 реализованы; каркас preview и каталог UI kit уже доступны.
2. B01–B03 → V01–V04: собрать общую оболочку, главную и поиск с интерактивным mobile Drawer.
3. B04/B05 → V05–V09: объявление, «О нас», вход и регистрация. Выбор фото относится к редактированию профиля и публикации, а не к стартовой форме регистрации.
4. V10–V13: профиль, редактирование и сообщения; до приёмки сверить неподтверждённые экраны с доступным актуальным дизайном.
5. V14–V18: четыре проектных шага публикации с сохранением локальных значений и фото.
6. Q01–Q03: визуальная сверка, доступность и переход новых экранов на собственный UI kit.

Ориентироваться на зависимости конкретных задач: не нужно ждать завершения всех компонентов, чтобы начать первые экраны. Новые представления размещаются в проектных слоях и сразу используют UI kit, а preview собирает их с демонстрационными данными. Подключение этих представлений к существующим сервисам и бизнес-сценариям — последующий этап за пределами этого плана.

## Критерий готовности каждой задачи

- Компонент или экран открывается в каталоге/preview без работающего backend.
- Использованы согласованные токены, ресурсы и компоненты UI kit.
- Есть desktop и mobile, проверены промежуточные ширины и длинный контент.
- Все перечисленные состояния доступны для просмотра; интерактивные элементы имеют работающую локальную демонстрацию.
- Для UI kit показаны варианты, размеры, состояния и пример использования.
- Проходят существующие frontend-проверки `npm run build`, `npm run lint`, `npm run test`; исходные неисправности фиксируются отдельно.
- Новые тесты нужны для значимого поведения: фокус overlays, клавиатурное управление, сохранение значений между шагами. Цвета/отступы проверяются визуально.
- К задаче приложены снимки desktop/mobile и краткое описание проверенного результата.

P01–P03 и K01–K11 представлены в `client/DESIGN.md`, `client/src/shared/assets/redesign-assets.md`, `client/src/preview/` и `client/src/shared/ui/`. В preview уже показаны девять демонстрационных экранов, но их разметка и локальные состояния пока находятся в `PreviewApp.tsx` на отдельных стилях. При выполнении B/V-задач их нужно заменить предметными компонентами в слоях проекта, принимающими данные и обработчики через props и использующими UI kit. Это отделяет готовность каркаса P03 от приёмки полноценных экранов.

До Q02 проверить, что все размеры `IconButton` соответствуют минимальной области нажатия 44 × 44 px из карты ресурсов. При V17 предусмотреть передачу выбранных файлов и главного фото из `UploadArea` в состояние шага, чтобы обзор V18 показывал фактический выбор. Снимки `docs/screenshots/` относятся к прежнему интерфейсу и не подтверждают Q01 для нового preview.
