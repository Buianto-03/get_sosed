# Ручной деплой production

Production обновляется вручную через GitHub Actions. Обычный деплой не требует подключения к серверу.

## Запуск

1. Дождитесь успешного запуска workflow **CI** для текущего коммита `release/initial` после push. Убедитесь, что задача `publish-images` тоже завершилась успешно.
2. Откройте **Actions → Ручной деплой production → Run workflow**.
3. Выберите ветку `release/initial`, оставьте поле `ci_run_id` пустым и нажмите **Run workflow**. Workflow выберет успешный CI для коммита, на который ветка указывала в момент запуска. Если такой CI не найден, деплой остановится.
4. Дождитесь результата задачи **Проверить образы и выполнить деплой**. Откройте сайт и проверьте объявления и изображения.

Чтобы явно выбрать предыдущую версию, можно указать числовой ID успешного запуска CI в поле `ci_run_id`. Его можно взять из адреса запуска: `.../actions/runs/123456789`. Это не номер коммита и не номер запуска с символом `#`. Развёртывание старой версии не отменяет миграции базы: заранее проверьте совместимость схемы.

Workflow проверяет выбранный CI и артефакт `deploy-images-<commit>`, затем запускает SSM-документ `GetSosed-DeployProduction`. Артефакты хранятся ограниченное время: для удалённого или истёкшего артефакта потребуется доступный успешный запуск CI с артефактом.

## Что происходит на сервере

SSM запускает `/usr/local/lib/get-sosed/deploy-production.sh`. Сценарий скачивает образы клиента и сервера по digest, сохраняет копию базы в `~/get-sosed-production/backups/`, применяет миграции, обновляет контейнеры и проверяет ответ API на локальном адресе.

Копия базы перед деплоем хранится на том же EC2; она не заменяет копию вне сервера. Сценарий не сохраняет загруженные изображения и не восстанавливает базу автоматически. Перед миграциями важно иметь актуальные копии базы и файлов в отдельном месте и понимать совместимость миграций со старой версией приложения. Во время переключения контейнеров сайт может быть недоступен.

Код сценария в репозитории находится в `scripts/deploy-production.sh`, но сервер выполняет установленную копию в `/usr/local/lib/get-sosed/`. Коммит или деплой образов не обновляет эту копию автоматически. Конфигурация Compose и Caddy на сервере также не обновляется автоматически при деплое образов.

## Если деплой завершился с ошибкой

Откройте шаг **Запустить деплой и дождаться результата** в GitHub Actions и найдите последнюю выполненную операцию. По ID команды из лога можно посмотреть результат в **AWS Systems Manager → Run Command → Command history**.

Не запускайте повторный деплой, пока не ясно, на каком этапе возникла ошибка. Миграции могли уже изменить базу или контейнеры могли обновиться частично; автоматического отката нет. Если ожидание в GitHub прервалось или workflow отменили, отдельно проверьте состояние команды в Systems Manager: отмена workflow не подтверждает остановку команды на сервере.

Токен GHCR хранится в Systems Manager Parameter Store как SecureString. Не копируйте его значение в репозиторий, логи или обращения за помощью.
